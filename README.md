# C Compiler Front End Using Flex and Bison

## 1. Project Overview

This project implements a simple C compiler front end that translates a supported subset of C into **Three-Address Code (TAC)**.

The lexer is built using **Flex**, and the parser is built using **Bison**. The parser checks the program's syntax, tracks declared variables and their types, handles supported expressions and control-flow statements, and prints the generated TAC.

> **Note:** This is an educational compiler front end for a limited subset of C. It is not a complete C compiler.

## 2. Assignment Requirements

The supported subset is designed to include:

- `int` and `float` variables
- Variable declarations and assignments
- Arithmetic expressions
- Implicit type promotion/conversion in supported expressions
- `if`, `if-else`, and nested `if-else` statements
- `while` loops
- Relational/equality operators supported by the grammar
- Blocks enclosed in braces
- Three-Address Code generation using temporary variables and labels

The assignment constraints are fewer than 10 variables and fewer than 50 lines of source code.

## 3. Files in This Project

| File | Description |
|---|---|
| `front.l` | Flex rules that recognize keywords, identifiers, literals, operators, and punctuation |
| `front.y` | Bison grammar, symbol table, type handling, and TAC generation |
| `sample.c` | Sample input program used to test the compiler front end |
| `front.tab.c` | C source generated by Bison |
| `front.tab.h` | Token definitions generated by Bison |
| `lex.yy.c` | C source generated by Flex |
| `compiler.exe` | Executable produced by GCC |
| `output.txt` | Optional file containing the compiler's output |

The generated files (`front.tab.c`, `front.tab.h`, and `lex.yy.c`) are created during the build process. `compiler.exe` and `output.txt` are created when you compile and run the project.

## 4. Prerequisites

This guide uses **MSYS2 UCRT64** on Windows.

Install MSYS2 from the official website:

<https://www.msys2.org/>

Open **MSYS2 UCRT64** from the Start menu and install the required tools:

```bash
pacman -S --needed flex bison gcc
```

Check that the tools are available:

```bash
bison --version
flex --version
gcc --version
```

## 5. Build Instructions

Open the **MSYS2 UCRT64** terminal and move to the project directory. For example, if the folder is `D:\Compiler_Frontend`, run:

```bash
cd /d/Compiler_Frontend
```

Confirm that the source files are present:

```bash
ls
```

### Step 1: Generate the parser with Bison

```bash
bison -d -o front.tab.c front.y
```

This generates `front.tab.c` and `front.tab.h`.

Bison may display warnings about empty grammar rules. Such warnings do not necessarily stop code generation; review them if you are maintaining the grammar.

### Step 2: Generate the lexer with Flex

```bash
flex -o lex.yy.c front.l
```

This generates `lex.yy.c`.

### Step 3: Compile the generated C files

In the MSYS2 UCRT64 environment, the following command works when the source does not require linking the Flex library:

```bash
gcc -o compiler.exe front.tab.c lex.yy.c
```

If your version of `front.l` requires `yywrap`, add `%option noyywrap` near the top of `front.l`, before the first `%%`, then regenerate the lexer and compile again. Do not add a second `%%` if the file already has the normal two Flex section separators.

## 6. Run the Compiler

To process `sample.c` and display TAC in the terminal:

```bash
./compiler.exe < sample.c
```

The output should contain a header, generated instructions, and a completion message. The exact temporary-variable and label numbers depend on the input program and grammar.

## 7. Save the Output to a Separate File

To write the generated output to `output.txt` instead of displaying it in the terminal:

```bash
./compiler.exe < sample.c > output.txt
```

This creates or overwrites `output.txt` in the current directory.

To view the saved output in the terminal:

```bash
cat output.txt
```

To open it in Notepad:

```bash
notepad output.txt
```

To both display the output and save it at the same time:

```bash
./compiler.exe < sample.c | tee output.txt
```

**Important:** The `>` operator overwrites an existing `output.txt`. Use `>>` instead of `>` if you want to append output to the file.

## 8. Example Input

The following is a representative example of the supported syntax. The actual `sample.c` in your project is the input used when running the commands above.

```c
int a, b, c;
float x;

a = 2;
b = 5;
x = 2.5;

while (a < b) {
    if (x > 1.0) {
        if (a != 3)
            c = a + b;
        else
            c = a - b;
    } else {
        c = a * b;
    }
    a = a + 1;
}
```

## 9. Understanding the TAC Output

TAC breaks complex expressions and control flow into simpler instructions.

For example, the expression:

```c
c = a + b;
```

may be translated into:

```text
t0 = a + b
c = t0
```

- `t0` is a temporary variable used to store an intermediate result.
- `L0`, `L1`, and similar names are labels used as jump targets.
- `if !t0 goto L1` means to jump to `L1` when the condition stored in `t0` is false.
- `goto L0` performs an unconditional jump, such as returning to the beginning of a loop.

## 10. Limitations

This project supports only the syntax implemented in `front.l` and `front.y`. It does not implement all of C. Features such as pointers, arrays, functions, and other unsupported language constructs should not be assumed to work. Consult the grammar for the exact supported syntax.

The generated TAC is an intermediate representation; this project does not generate machine code or execute the input C program.

## 11. Troubleshooting

### `bison: command not found`

Make sure you are using the **MSYS2 UCRT64** terminal and have installed Bison:

```bash
pacman -S --needed bison
```

### `flex: command not found`

Install Flex:

```bash
pacman -S --needed flex
```

### `cannot find -lfl`

Try compiling without `-lfl`:

```bash
gcc -o compiler.exe front.tab.c lex.yy.c
```

If you see an `undefined reference to yywrap` error, add `%option noyywrap` to `front.l` before the first `%%`, regenerate the lexer, and compile again.

### `output.txt` is empty

Check that `sample.c` contains valid input for the supported grammar and that the compiler exits successfully. Remember that `>` redirects both standard output and any normal messages written there; diagnostic errors may appear separately on standard error.

## 12. Summary

This project demonstrates the core front-end stages of a simple compiler:

1. **Lexical analysis:** Flex converts source characters into tokens.
2. **Syntax analysis:** Bison checks the token sequence against the grammar.
3. **Symbol-table and type handling:** The grammar tracks variables and supported types.
4. **Intermediate-code generation:** Expressions and control-flow statements are translated into Three-Address Code.

To rebuild and save the result, run:

```bash
bison -d -o front.tab.c front.y
flex -o lex.yy.c front.l
gcc -o compiler.exe front.tab.c lex.yy.c
./compiler.exe < sample.c > output.txt
```
